# 备份、恢复与回滚

## 发布前

1. 停止写入或建立可验证的一致性快照。
2. 使用组织批准的工具备份 PostgreSQL、`app_data`、上传文件和报告；密钥材料单独备份并限制访问。
3. 记录应用 commit、Alembic revision、镜像摘要、备份时间和校验值。不要把备份或校验明细提交到仓库。
4. 在隔离环境恢复备份，运行 `alembic current`、关键行数核对和最小登录/读取/导出检查。

## 应用回滚

从上一个已验证 commit 构建新镜像并滚动替换。不要使用 `git reset --hard` 修改部署记录。若新版本已经写入不兼容数据，应先由数据库负责人确认迁移回滚是否安全。

## 数据库回滚

`alembic downgrade -1` 仅用于自动化可逆性检查，不是生产回滚授权。生产环境优先采用向前修复；必须降级时先备份，再在副本演练并核对会被删除或转换的列。无法证明无数据丢失时，恢复已验证快照。

## 恢复验收

确认就绪检查、用户/合同/版本/风险/审计数量、附件下载、报告导出和任务状态；记录实际 RPO/RTO。未经真实演练不得填写恢复时长承诺。

# 自建法律知识库验收说明

## 技术基线

- 后端：Python 3.12、FastAPI、Pydantic、SQLAlchemy 2。
- 数据库：生产配置沿用 PostgreSQL；本地未启用数据库时沿用项目现有 JSON 文档存储。
- 迁移：Alembic，新增迁移 `20260802_0008_legal_knowledge.py`，不删除或覆盖旧表。
- 前端：Vue 3、TypeScript、Vite、Element Plus。
- AI 审查链：分类、条款提取、规则检查、法律知识检索、合规检查、结果校验、结果持久化。

## 初始化

数据库部署执行：

```powershell
python -m alembic upgrade head
```

本地验收默认数据目录为 `data/legal-knowledge/`。管理员也可在“法律知识库”页面点击“导入待核验演示结构”，或调用：

```text
POST /api/v1/legal-knowledge/imports/demo
```

演示模板源文件为 `src/contract_review/knowledge/legal_demo_seed.json`。其中仅包含 14 个风险主题的待核验占位结构，不包含编造的法律原文，也不会进入正式审查引用。

## 法律数据录入

1. 以管理员账号进入“法律知识库 → 法律法规”。
2. 新建法律文件，录入来源名称、官方来源地址、版本、效力状态和全文。
3. 未完成来源与正文核验前保持“待核验”；只有管理员确认后才能改为“已核验”。
4. 在“法律条文”中选择法律文件及具体版本，录入条号、正文、关键词、主题和适用合同类型。
5. 在“风险规则”中配置合同类型、条款类型、触发关键词、风险说明、修改建议和推荐条款，并关联一个或多个已存在法条。
6. 法律修订时编辑法律文件会新建不可覆盖的版本记录；旧版本继续保留。

已核验内容必须具有官方来源地址和正文。待核验、停用、已废止或尚未施行的条文不会作为正式审查依据。

## 验收步骤

1. 老板或管理员登录，确认侧栏出现“法律知识库”。
2. 新建法律文件并确认版本历史出现首个版本。
3. 新建具体法条，选择对应法律版本。
4. 新建风险规则并关联该法条；输入不存在的法条 ID 时接口应返回 422。
5. 上传 `samples/demo_procurement_contract_risky.docx` 或软件开发服务合同。
6. 发起 AI 审查，查看风险说明、后果、修改建议、推荐条款和置信度。
7. 对命中的风险查看法律名称、条号、内容摘要、来源和版本，并打开法条详情。
8. 对未检索到可靠法条的风险，确认页面显示“未匹配到已核验法律依据”。
9. 使用员工账号登录，确认只有“法律检索”，且只能看到已公开、已核验、当前有效的条文。
10. 员工访问 `/legal-knowledge` 应进入 403 页面；直接调用管理接口也应返回 403。
11. 修改法律文件版本，确认旧版本未被覆盖且“版本记录”同时保留新旧版本。
12. 检查审查风险与法条关联记录以及审计日志中的法律数据新增、修改、停用、导入操作。

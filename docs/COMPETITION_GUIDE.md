# 大学生比赛优化指南

## 项目定位

项目名称建议使用：企业级多源合同智能审查与风险决策平台。

一句话介绍：系统面向中小企业、法务助理和采购审批场景，使用 FastAPI、LangGraph 和外部大模型 API，将 PDF、Word、扫描件合同转化为结构化要素、风险评分、法律依据和可导出的审查报告。

## 评审关注点

比赛评审通常不只看“能不能调用大模型”，更看以下四点：

1. 真实问题：合同审查耗时、标准不一致、非结构化文件多、低算力设备难以本地部署大模型。
2. 技术闭环：多源解析、Multi-Agent 编排、RAG 依据检索、风险量化、报告导出、历史留痕。
3. 可解释性：每个风险点要有依据、等级、修改方向和 Agent 处理轨迹。
4. 可落地性：普通电脑能运行，API Key 可替换，数据可以本地保存，报告能交付。

## 当前已具备的比赛亮点

- 多源输入：支持 Word、PDF、图片扫描件合同。
- 多智能体协同：协调者、提取者、合规审查、反馈修改四类 Agent 通过 LangGraph 串联。
- 外部模型适配：支持 DeepSeek/OpenAI 兼容接口，不在本地加载大模型。
- 风险量化：输出风险分、安全分、总体等级和维度评分。
- 可解释审查：内置法律法规摘要和企业内控规则，支持依据检索。
- 报告交付：支持 JSON、Word、PDF 导出。
- 历史留痕：记录最近审查任务，便于演示和后续审计。
- 协同轨迹：响应中保留 Agent 执行动作和输出摘要，能展示系统过程。

## 建议继续打磨的高分方向

### 1. 数据集与评测

准备 20 到 50 份脱敏合同样本，覆盖采购、销售、服务、租赁、保密、劳动外包等类型。每份样本人工标注 3 到 8 个风险点，形成 `合同文本 - 标准风险点 - 标准修改建议` 的评测集。

建议指标：

- 风险召回率：系统找出的标准风险点占比。
- 风险准确率：系统风险点中真实有效的占比。
- 建议可采纳率：法务或老师评价建议条款是否可直接修改。
- 平均审查耗时：单份合同从上传到报告生成的时间。

### 2. 知识库升级

当前是轻量关键词检索，适合毕业设计演示。比赛版可以升级为向量检索：

- 使用 `sentence-transformers` 或云端 embedding API 生成法规和制度片段向量。
- 使用 FAISS、Chroma 或 SQLite-VSS 做本地检索。
- 把检索命中的法规片段和风险点建立引用关系。

### 3. 企业级能力

建议逐步加入：

- 用户和角色：法务、业务、管理员。
- 审批流：审查完成后进入人工复核、退回修改、确认归档。
- 合同类型模板：采购合同、销售合同、服务合同分别使用不同审查规则。
- 审查记录审计：记录上传人、审查时间、模型版本、规则版本。
- 敏感信息脱敏：对统一社会信用代码、手机号、账户信息做展示脱敏。

### 4. 页面与答辩表达

答辩页面应强调“工作台”，不是普通上传页面。建议展示顺序：

1. 导入合同。
2. 展示 Agent 协同轨迹。
3. 展示风险评分和风险维度。
4. 展示风险卡片。
5. 展示依据检索。
6. 下载 PDF/Word 报告。

### 5. 获奖材料组合

建议准备以下材料：

- 5 分钟路演 PPT。
- 8 到 10 分钟系统演示视频。
- 项目说明书。
- 技术架构图。
- 测试报告。
- 用户使用手册。
- 脱敏合同样例和审查报告样例。

## 答辩核心话术

不要只说“我用了大模型”。建议这样说：

本系统把合同审查拆成多个专业 Agent，并通过 LangGraph 固定协同流程，避免单次大模型问答不可控的问题。系统先用确定性解析和规则审查保证基础可靠性，再用 DeepSeek 等外部大模型增强语义理解和条款修改建议。最终输出风险量化、依据检索和可下载报告，使合同审查从“经验判断”变成“可追踪、可解释、可交付”的流程。
